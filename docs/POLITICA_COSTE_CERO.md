# POLÍTICA OBLIGATORIA: COSTE ADICIONAL CERO (IBEROS)

**Aplicación:** todo IberOS (Core científico, Dama de Ilici, La Picola, sitio web, copia de seguridad, documentación, CI/CD, investigación, bibliografía, IA, plugins, conectores, automatizaciones y difusión).

**Regla innegociable:** no generar, aceptar ni comprometer gasto adicional alguno (0 €), incluyendo pagos únicos, suscripciones, créditos, recargas, pay-as-you-go, APIs, servicios con facturación, ampliaciones de hosting, certificados y cuotas por superar límites gratuitos. Ningún proceso puede contratar un servicio ni activar una prueba que requiera medio de pago.

## Decisiones obligatorias

1. Antes de usar una herramienta o servicio, **verificar que esa ejecución concreta no genera cargos ni obliga a introducir tarjeta o recargar saldo**. No asumir que un servicio es gratuito por tener una prueba o un plan con nombre «free».
2. Priorizar software abierto y recursos gratuitos ya disponibles: GitHub repositorios públicos, GitHub Pages, ejecutores estándar de GitHub Actions para repositorios públicos dentro de límites gratuitos, Python/Node locales, datos públicos con licencias adecuadas y copias del propio proyecto.
3. **Prohibido** usar servicios, APIs, navegadores remotos, monitores y procesos de terceros que cobren por ejecución, crédito, consulta, almacenamiento, consumo, tráfico o volumen. Esto incluye añadir dinero a una cartera vacía. Un enlace de pago no es una alternativa aprobada.
4. Si una herramienta resulta ser de pago o no puede demostrarse que esta acción es gratuita, **detener esa vía, no repetir la llamada y sustituirla por una comprobación gratuita**. Comunicar qué quedó bloqueado y por qué sin fingir que se ejecutó.
5. No habilitar nunca autopagos, renovaciones de pago, servicios adicionales, facturación por exceso de cuota ni upgrades. Configurar límites de gasto cero cuando la plataforma lo permita; cancelar procesos que estén próximos al límite sin activar coste.
6. No usar automatizaciones recurrentes de coste incierto. Los trabajos de CI/CD y las pruebas intensivas deben ser acotados y ejecutarse como lotes tras validación; evitar lanzamientos duplicados o infinitos.
7. Preservar las copias de seguridad y el dominio existente sin alterar registros de correo ni servicios de terceros. **Un dominio propio ya registrado puede tener renovación de pago futura**: ese coste preexistente no debe ocultarse ni autoriza una renovación automática.
8. Ningún requisito científico, comercial o de publicación justifica una excepción implícita. Ante un bloqueo, documentar la alternativa gratuita o declararlo pendiente.
9. En revisiones y PR: explicitar «Coste adicional previsto: 0 €» y confirmar que las dependencias, herramientas, recursos y ejecuciones propuestas cumplen esta política.
10. Esta norma **no altera** el estado de validación científica: la evidencia epigráfica, las hipótesis y las traducciones propuestas deben mantener sus controles independientes.

## Criterio para el cierre

Un trabajo se considerará terminado únicamente si: (a) cumple el objetivo verificable, (b) no ha generado ni comprometido nuevos gastos y (c) no ha deteriorado el respaldo o la trazabilidad científica. Ante falta de capacidad gratuita, describir el resultado parcial sin prometer pagos ni futuras ejecuciones no autorizadas.

**Vigente desde el 12 de noviembre de 2026.** La política se conserva en el repositorio y se comunica a colaboradores y agentes de automatización.
